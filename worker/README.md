# 웹판 배포 (Cloudflare Workers)

바탕화면 위젯과 화면 코드(`ui/`)를 완전히 같이 쓰는 브라우저판이다. 서버는
토큰을 쥐고 노션과 이야기하는 얇은 중계층 하나뿐이고, 데이터는 노션 그
자체이니 별도 DB가 없다.

**로그인 화면이 없다.** 문을 지키는 것은 Cloudflare Access뿐이므로, 배포하자마자
아래 Access 설정까지 반드시 끝낸다. 그 전까지는 URL을 아무에게도 공유하지 않는다.

여러 사람이 각자 자기 할 일만 보게 하려면 아래 **팀 모드**를 참고한다.

## 사전 준비 (사람이 직접, 한 번만)

1. https://dash.cloudflare.com 에 무료 계정 (신용카드 필요 없음)
2. Node.js 설치 (wrangler가 필요로 한다)

## 배포

```bash
cd worker
npm install
npx wrangler login          # 브라우저가 뜨고 Cloudflare 로그인
npx wrangler secret put NOTION_TOKEN
# 프롬프트가 뜨면 노션 Integration 토큰을 붙여넣는다.
# 이 토큰은 wrangler가 Cloudflare에 암호화해 저장할 뿐, 이 저장소
# 어디에도, 이 터미널 기록에도 평문으로 남지 않는다.
npx wrangler deploy
```

배포가 끝나면 `https://todo-widget-web.<계정이름>.workers.dev` 같은
주소가 나온다. **이 주소를 아직 아무에게도 주지 않는다.**

## Cloudflare Access로 잠그기 (필수)

Cloudflare 대시보드 → Zero Trust → Access → Applications → **Add an
application** → Self-hosted.

- Application domain: 위에서 받은 `*.workers.dev` 주소
- Policy: `Include` → `Emails` → 본인 이메일 하나만
- 세션 길이는 편한 대로 (예: 24시간)

저장하면 그 주소에 접속할 때마다 Cloudflare 로그인 화면이 먼저 뜨고,
등록한 이메일로만 통과한다. 50명까지 무료다.

## 팀 모드 (여러 사람이 각자 자기 것만 보기)

켜기 전까지는 위에 적힌 대로 성준 혼자 쓰는 상태 그대로다. `TEAM` 시크릿을
넣는 순간부터 팀 모드로 바뀐다.

누가 접속했는지는 **Access가 서명해 보낸 토큰**에서만 꺼낸다. 브라우저가
보내는 헤더나 본문 값은 하나도 믿지 않는다. 거르는 일도 전부 워커가 하므로,
남의 항목은 애초에 브라우저로 나가지 않는다 — 개발자도구를 열어도 없다.

| | 보는 것 | 고치는 것 |
|---|---|---|
| 관리자 (admins에 적힌 사람) | 개인 · 팀 전체 | 전부 |
| 팀원 | 팀 DB 전체 (담당자 줄로 사람별 전환) | **자기가 담당자인 것만** |

팀이 서로의 할 일을 열어 두기로 해서 보는 것은 전원 공개다. 고치는 것은 자기
것만인데, 남의 할 일을 실수로 완료 처리하거나 지우는 일을 막기 위해서다. 화면은
팀원에게 자기 것부터 보여주고, 동료는 눌러서 본다.

팀에 열지 않을 일(개인 사정 같은 것)은 **팀 DB에 넣지 않는 것**으로 가린다.
성준의 개인 DB는 애초에 팀원에게 보이지 않는다 — 워커가 팀원에게는 팀 DB
하나만 열어 주기 때문이다(`sourcesFor`). 팀 DB 안에서 사람별로 가리는 장치는
두지 않았다. 팀 DB에 올라간 것은 팀원끼리 서로 다 본다.

팀 DB는 성준 개인 워크스페이스의 비공개 DB다. **팀원에게 노션 자체는 공유하지
않는다** — 공유하는 순간 워커가 거르는 의미가 없어진다. Integration
(`notion_todo-widget`)만 연결해 두면 된다.

### 1. AUD 태그 채우기

Zero Trust → Access → Applications → 해당 앱 → 개요의 **Application Audience
(AUD) Tag**를 복사해 `wrangler.toml`의 `ACCESS_AUD`에 넣는다. `ACCESS_DOMAIN`은
팀 도메인(`ulicktodo.cloudflareaccess.com`)이다.

둘 중 하나라도 비어 있으면 팀 모드는 **켜지지 않고 막힌다**. 열려버리는 쪽으로
넘어가지 않는다.

### 2. 사람 등록

```bash
cd worker
npx wrangler secret put TEAM
```

프롬프트에 한 줄 JSON을 붙여넣는다. `members`의 값은 노션 팀 DB의 `담당자`
선택지와 **글자까지 똑같아야** 한다.

```json
{"admins":["나@회사.com"],"members":{"나@회사.com":"성준","가영@회사.com":"가영","창준@회사.com":"창준","여림@회사.com":"여림"}}
```

이메일은 시크릿으로 들어가므로 저장소에 남지 않는다. 사람이 바뀌면 이 명령을
다시 실행해 통째로 새로 넣는다.

### 3. Access 정책에 같은 이메일 넣기

Zero Trust → Access → Applications → 앱 → 정책에서 `Emails`에 네 명을 모두
추가한다. **두 군데가 따로 논다** — Access 정책은 "문을 통과할 수 있는가",
`TEAM` 시크릿은 "통과한 사람이 누구인가"다. 정책에만 있고 시크릿에 없으면
"등록되지 않은 사용자다"가 뜬다.

### 4. 배포

```bash
npx wrangler deploy
```

## 팀원이 자기 Claude에서 쓰게 하기 (MCP)

워커의 `/mcp` 가 팀원의 Claude Code가 붙는 문이다. 노션을 직접 열어 주지 않고 이
문만 여는 이유는, 노션에 권한을 주는 순간 그 사람이 **전원 할 일을 다 보게** 되기
때문이다. `/mcp` 는 화면(`/api/*`)과 **똑같은 신원 확인과 거르기**를 지나므로
여기서도 자기 것만 오간다.

사람 대신 프로그램이 Access를 통과해야 하므로 **서비스 토큰**을 쓴다. 토큰
하나가 사람 하나를 가리키고, 워커는 토큰의 Client ID로 누구인지 판단한다.

### 1. 서비스 토큰 만들기 (사람마다 하나)

Zero Trust → 액세스 제어 → **서비스 자격 증명** → 서비스 토큰 만들기.
이름은 사람 이름으로 (`가영`, `창준`, ...). **Client Secret은 만들 때 한 번만
보인다** — 못 받았으면 지우고 다시 만든다.

### 2. Access 정책에 허용 추가

애플리케이션 → `todo-widget-web` → 정책 → **새 정책**:
작업 **서비스 인증(Service Auth)**, 포함 규칙 **서비스 토큰** → 만든 토큰들 선택.

기존 이메일 정책은 그대로 둔다. 사람은 이메일로, 프로그램은 토큰으로 들어온다.

### 3. 안내 파일 만들기

```bash
python scripts/make_member_guide.py
```

지금 쓰는 `TEAM` JSON을 붙여넣고 사람마다 Client ID/Secret을 넣으면,
`guides/<이름>.md` 와 **새 `TEAM` JSON**이 나온다. 팀원은 그 .md 하나를 자기
Claude에 던지면 설정이 끝난다.

`admins`에 있는 사람의 토큰은 스크립트가 알아서 `admins`에도 넣는다. 이걸
빠뜨리면 관리자가 자기 Claude에서만 팀원처럼 보이는데, 알아채기 어렵다.

### 4. 새 TEAM 시크릿 넣기

```bash
cd worker
npx wrangler secret put TEAM
```

배포는 필요 없다. 시크릿은 넣는 즉시 적용된다.

`guides/`는 `.gitignore`에 있다. 토큰이 든 파일이므로 1:1로 건네고, 사람이
바뀌면 Cloudflare에서 그 토큰을 지운 뒤 `TEAM`에서도 빼면 그 순간 막힌다.

## 시험 돌려 보기

```bash
cd worker
npm test
```

워커를 실제로 돌려 본다. 노션과 Cloudflare Access를 흉내 내고, 시험 파일이 직접
만든 열쇠로 Access 토큰을 서명해 넣는다. **노션 토큰도 네트워크도 필요 없다.**

보는 것은 하나다 — 남의 것이 새어 나가지 않는가. 누가 어느 DB를 묻게 되는지,
거부된 요청이 노션에 쓰기를 시도조차 안 하는지까지 본다. 신원·권한 쪽을
고쳤으면 배포 전에 돌린다.

## 개인 할 일을 구글 캘린더에 (.ics 구독)

성준의 **개인 DB** 할 일을 달력 한 장(.ics)으로 내주고, 구글 캘린더가 그 주소를
구독하게 한다. 구글 승인도, OAuth도, 새 저장소도 필요 없다.

방향이 한쪽뿐이다 — **노션이 원본이고 구글은 읽기만 한다.** 구글이 주는 개인
iCal 주소(`.../basic.ics`)로는 반대로 쓸 수가 없다. 읽기 전용이라서다.

### 이 주소는 Access 밖에 있다

구글 서버는 로그인을 못 하므로, 이 한 길만 Cloudflare Access 앞이 아니라 뒤에
둔다. **문을 지키는 것은 주소에 박힌 난수 하나뿐이다.** 그래서:

- 나가는 것은 **개인 DB의 미완료 항목뿐이다.** 팀 DB는 이 문으로 안 나간다
  (`worker/test/worker.test.js`가 이걸 지킨다)
- 주소를 아는 사람은 제목을 다 본다. **링크를 아무 데도 붙여넣지 않는다** —
  메신저, 이슈, 문서 어디에도
- 새로 바꾸고 싶으면 아래 1번을 다시 하면 된다. 그 순간 옛 주소는 죽는다

### 1. 난수 만들어 넣기

```bash
openssl rand -hex 24          # 48자리. 이 값을 그대로 쓴다
cd worker
npx wrangler secret put ICS_TOKEN
```

시크릿이 없으면 이 길은 **아예 없다**(404). 켜는 것은 이 한 줄이다.

### 2. Access에 이 경로만 예외 두기

Zero Trust → Access → Applications → **Add an application** → Self-hosted:

- Application domain: `todo-widget-web.<계정>.workers.dev`, **Path: `feed`**
- Policy: Action **Bypass**, Include **Everyone**

경로가 더 자세한 앱이 먼저 걸리므로, `/feed/...`만 로그인 없이 열리고 나머지는
지금처럼 막힌 채로 있다. **이걸 빼먹으면** 구글이 로그인 화면을 받아 가서
"캘린더를 가져올 수 없습니다"가 뜬다.

### 3. 배포하고 구글에 물리기

```bash
npx wrangler deploy
```

구글 캘린더 → 왼쪽 **다른 캘린더 +** → **URL로 추가** →

```
https://todo-widget-web.<계정>.workers.dev/feed/<난수>.ics
```

### 알아둘 것

- **바로바로 반영되지는 않는다.** 다시 읽어 가는 주기는 구글이 정한다. 보통 몇
  시간, 늦으면 하루다. 우리 쪽에서 30분마다 봐 달라고 적어 보내지만 부탁일
  뿐이다. 즉시 반영이 필요하면 구글 캘린더 API를 쓰는 수밖에 없다
  (`docs/구글-캘린더-연동-계획.md`)
- 구독한 캘린더는 **구글에서 고칠 수 없다.** 노션이나 웹판에서 고치면 따라온다
- 마감일이 없는 할 일은 달력에 안 올라간다. 올릴 자리가 없다
- 완료하면 다음 갱신 때 사라진다
- 하루를 "바쁨"으로 잡지 않는다(`TRANSP:TRANSPARENT`). 남이 회의 잡는 데
  방해되지 않는다
- 그만두려면 `npx wrangler secret delete ICS_TOKEN`. 그 즉시 404가 된다

## 구글 캘린더에 실제로 써넣기 (아이폰까지 가는 길)

위의 `.ics` 구독은 **구글 안에서만** 보인다. 구글은 URL로 구독한 캘린더를 모바일
앱에 내려보내지 않으므로, 아이폰에서 보려면 캘린더에 **진짜 일정**이 있어야 한다.
그건 API로 쓰는 수밖에 없다.

**둘 다 켜지 않는다.** 같은 할 일이 두 번 보인다. 이쪽으로 가면 구글 캘린더에서
구독하던 .ics를 빼거나 `ICS_TOKEN` 시크릿을 지운다.

### 무엇이 바뀌나

| | .ics 구독 | API로 쓰기 |
|---|---|---|
| 반영 속도 | 몇 시간 (구글이 정한다) | **바로** |
| 아이폰 | **안 간다** | 간다 |
| 준비물 | 난수 하나 | GCP 서비스 계정 + 캘린더 공유 |
| 캘린더에서 고치면 | 안 됨(읽기 전용) | 됨. 다만 노션으로 돌아오진 않는다 |

### 1. 서비스 계정 만들기 (한 번)

1. console.cloud.google.com 에서 프로젝트 하나 만들고 **Google Calendar API**를
   "사용 설정"
2. **서비스 계정** 만들기 → 키 → **JSON 키 만들기** (파일이 받아진다)
3. 그 JSON 안의 `client_email`(`...@....iam.gserviceaccount.com`)을 복사해 둔다

구글 로그인 동의 화면도, 도메인 관리자 권한도 필요 없다. **개인 gmail로 된다.**

### 2. 할 일 전용 캘린더를 만들어 공유

구글 캘린더 → 설정 → **새 캘린더 만들기** (예: `Ulick 할 일`).

본 캘린더에 바로 쓰지 않는 이유는 둘이다 — 키가 새도 피해가 그 캘린더 하나로
끝나고, 할 일과 진짜 약속이 안 섞인다.

만든 캘린더 → 설정 → **특정 사용자와 공유** → **사용자 및 그룹 추가** →
1번의 `client_email`을 붙여넣고 권한은 **"일정 변경"**. 사람 계정이 아니라
검색으로는 안 뜨니 주소를 통째로 붙여넣는다. 그 위의 "변경 및 공유 관리"는
주지 않는다 — 쓰기에는 필요 없고, 그걸 주면 이 캘린더를 남에게 공유하는
권한까지 넘어간다.

**캘린더 ID**는 이 화면이 아니라 왼쪽 메뉴의 **캘린더 통합** 안에 있다
(`....@group.calendar.google.com`).

### 3. 시크릿 넣고 배포

```bash
cd worker
npx wrangler secret put CALENDAR
```

한 줄 JSON을 붙여넣는다 (`private_key`는 받은 JSON 파일에서 그대로 복사):

```json
{"provider":"google","client_email":"...@....iam.gserviceaccount.com","private_key":"-----BEGIN PRIVATE KEY-----\n...","calendar_id":"....@group.calendar.google.com","owner":"성준"}
```

```bash
npx wrangler deploy
```

### 개인용 캘린더를 따로 두기 (권장)

캘린더를 하나만 쓰면 회사 할 일과 개인 할 일이 한 칸에 섞인다. 화면을 남에게
보여줄 일이 있으면 그게 곧 노출이다.

캘린더를 하나 더 만들고(예: `회사개인 동기화용`) **같은 서비스 계정에게 똑같이
"일정 변경" 권한으로 공유**한 뒤, 시크릿에 `personal_calendar_id`를 더하면 된다.
그러면 구글 캘린더 왼쪽에서 개인 쪽만 체크를 꺼 둘 수 있다.

```json
{"provider":"google","client_email":"...","private_key":"...","calendar_id":"회사용...","personal_calendar_id":"개인용...","owner":"성준"}
```

- `personal_calendar_id`를 안 적으면 예전처럼 한 캘린더에 다 들어간다
- 대조는 캘린더마다 따로 한다. 그래서 항목이 개인 DB에서 팀 DB로 옮겨 가면
  다음 차례에 옛 캘린더에서 저절로 사라진다
- 완료하거나 지울 때는 어느 쪽에 있었는지 모르므로 두 캘린더를 다 훑는다

### 무엇이 올라가나

- **개인 DB는 전부** (`personal_calendar_id`가 있으면 그쪽으로)
- **팀 DB는 `owner`에 적은 사람 것만** (`calendar_id` 쪽으로)**.** `owner`를 빼면 팀 항목은 하나도 안
  올라간다. 팀원 할 일이 성준 캘린더로 새지 않게, 올릴지 말지는 워커가 노션에
  직접 물어서 정한다
- 마감일이 없으면 안 올라간다. 완료하거나 지우면 일정도 사라진다
- 한 방향이다(노션 → 구글). 구글에서 날짜를 옮겨도 노션은 모른다

### 언제 올라가나 — 길이 둘이다

| 어디서 넣었나 | 언제 캘린더에 |
|---|---|
| 웹 투두 (추가·완료·마감일 변경·삭제) | **바로** |
| 클로드(MCP), 위젯, 노션에서 직접 | **10분 안에** |

클로드와 위젯은 노션에 직접 쓰고 이 워커를 지나가지 않는다. 그래서 워커가
스스로 양쪽을 맞춘다. 맞출 기회가 **둘**이다:

1. **시계** — `wrangler.toml`의 `[triggers]`가 10분마다 `index.js`의
   `scheduled`를 깨운다
2. **화면을 열 때** — `/api/*` 요청 끝에 10분에 한 번씩 같이 맞춘다
   (`index.js`의 `maybeSync`)

둘을 다 두는 이유는, 시계가 등록은 되는데 안 깨어나는 것을 봤기 때문이다.
2번은 화면을 안 열면 안 도는 길이라 시계를 대신하지는 못한다 — 시계가
본줄이고 2번은 받침이다.
깨어나지 않는 것은 밖에서 알 방법이 없다 — 아무 일도 안 일어난 것과 똑같이
보인다. 화면은 하루에도 여러 번 여니까, 2번만으로도 실질적으로 같은 일을 한다.
둘 다 같은 `reconcile`을 부르고, 대조해서 맞추는 방식이라 두 번 돌아도 결과가
같다.

맞추는 방식은 **기억이 아니라 대조**다. 무엇이 바뀌었는지 적어 두지 않고,
매번 노션과 캘린더를 통째로 읽어 같게 만든다. 그래서 몇 번을 돌리든 결과가
같고, 한 번 실패해도 다음 차례에 저절로 복구된다.

지우는 것은 **워커가 만든 일정(id가 `todo`로 시작)**뿐이다. 같은 캘린더에
사람이 직접 넣은 일정은 사라지지 않는다.

주기를 바꾸려면 `wrangler.toml`의 `crons` 값을 고치고 다시 배포한다.

### 시계가 도는지 확인하기

`npx wrangler tail`은 **켜 둔 동안만** 보여준다. 새벽에 돌았는지 같은 것은
못 본다. 그래서 `[observability]`를 켜 뒀다 — Cloudflare 대시보드의
**Workers & Pages > todo-widget-web > Logs**에 지난 실행이 남는다.
깨어날 때마다 이 줄이 찍힌다:

```
[calendar] 시계가 깨웠다 (*/10 * * * *)
[calendar] 동기화: 노션 N건, 올림 N, 지움 N
```

**먼저 로그 자체가 살아 있는지부터 본다.** 대시보드 Logs(관찰 가능성 > Events)
화면이 `0 Success / 0 Errors`로 **통째로 비어 있으면**, 시계 얘기가 아니라
로그가 안 쌓이고 있는 것이다 — 그 시간 동안 웹 화면을 한 번도 안 열었거나,
배포된 워커가 `[observability]`가 들어가기 전 버전이라서다. 웹 화면을 한 번
열고 2분 뒤에 다시 봐서 그 접속(fetch)이 찍히는지 확인한다. 안 찍히면
`npx wrangler deploy`부터 다시 한다. 접속은 찍히는데 아래 줄만 없을 때가
비로소 "시계가 안 돈다"다.

로그에 이 줄이 하나도 없으면 시계가 등록만 되고 안 도는 것이다.
그때는 아래 "밖에서 두드려 깨우기"로 넘어간다. 그때는
대시보드의 **Settings > Triggers > Cron Triggers**에 `*/10 * * * *`가 실제로
있는지 보고, 없으면 거기서 직접 추가한다. (배포 출력에 `schedule:`이 찍혀도
실제로 안 걸려 있던 적이 있다.)

### 밖에서 두드려 깨우기 (시계가 안 돌 때)

`/sync/<토큰>` 을 부르면 그 자리에서 맞추기가 돈다. 무료 cron 서비스
(cron-job.org 등)가 10분마다 이 주소를 부르게 해 두면 시계를 대신한다.

```bash
npx wrangler secret put SYNC_TOKEN     # 32바이트 이상 난수
```

주소: `https://todo-widget-web.<계정>.workers.dev/sync/<토큰>`

**이 문은 Access 밖이다** — 밖에서 두드리는 것이 요점이라 로그인을 시킬 수가
없다. 그래서 `/feed/`와 같은 규칙을 지킨다:

- `SYNC_TOKEN`이 없으면 길 자체가 없다(404). 토큰이 틀려도 404다
- **나가는 것이 없다.** 돌려주는 것은 `ok` 세 글자뿐이라, 주소가 새더라도
  할 일 제목도 건수도 보이지 않는다. 할 수 있는 일은 "맞춰라" 시키는 것뿐이다
- 그래도 주소는 흘리지 않는다. 남이 계속 두드리면 노션·구글 호출이 는다

Cloudflare Access가 이 호스트 전체를 막고 있다면, `/sync/*`에 **Bypass 정책**을
하나 만들어야 한다(`/feed/*`와 같은 방식).

### 아이폰

그 캘린더는 구글 계정에 딸린 **진짜 캘린더**이므로, 아이폰에서 구글 계정을
쓰고 있으면 저절로 따라온다. 안 보이면 구글 캘린더 앱 설정이나
calendar.google.com/syncselect 에서 그 캘린더가 켜져 있는지 본다.

## 로컬에서 미리 보기

```bash
cd worker
cp .dev.vars.example .dev.vars   # NOTION_TODO_TOKEN 대신 NOTION_TOKEN 키로 채운다
npx wrangler dev
```

`.dev.vars`는 로컬 전용이고 git에 올라가지 않는다 (`.gitignore` 참고).
배포된 워커에는 영향을 주지 않는다 — 그쪽은 `wrangler secret put`으로
넣은 값을 쓴다.

## 업데이트

화면(`ui/`)이나 노션 호출 로직(`worker/index.js`)을 고친 뒤:

```bash
cd worker
npx wrangler deploy
```

토큰을 다시 넣을 필요는 없다. 시크릿은 배포와 별개로 유지된다.

## 위젯과 다른 점

`ui/app.js`는 `window.Backend`라는 창구 하나만 알고, 그 뒤가 위젯인지
웹인지는 모른다.

- 위젯: `ui/adapter-widget.js`가 `pywebview.api`를 부른다
- 웹: `ui/adapter-web.js`가 `fetch("/api/...")`로 이 워커를 부른다

`Backend.chrome`이 `false`면 항상 위 / 트레이로 숨기기 / 종료 / 크기 조절
손잡이처럼 OS 창에서만 의미 있는 조작을 화면에서 숨긴다(`app.css`의
`.widget.web` 규칙). 브라우저 탭은 원래 있는 새로고침·닫기로 충분하다.
