# Ulick To-do — 다른 저장소의 클로드 코드에게 주는 안내

> **안내 v2** (2026-10-06, 커밋 `b55d1d2`) — 성준이 "이 안내 버전 뭐야?"라고 물으면
> 이 줄을 그대로 답한다. 원본은 `PangJuck/notiontodoweget` 의
> `docs/ulick-todo-안내-v2-20261006.md` 다. 거기 것과 다르면 이 파일이 낡은 것이다.

**두는 자리** — `~/.claude/CLAUDE.md` 의 아래 표시 사이. 그러면 모든 저장소의
세션이 받는다. 한 저장소에만 쓰려면 그 저장소의 `CLAUDE.md` 에 넣는다.

```
<!-- ulick-todo-안내 시작 -->
   ...여기...
<!-- ulick-todo-안내 끝 -->
```

**표시로 감싸는 이유** — 판을 올릴 때 사이만 갈아끼우면 된다. 표시가 없으면
낡은 안내가 밑에 그대로 남아 새 안내와 싸운다. 넣을 때 표시부터 만든다.

---

## 이게 뭔가

`ulick-todo` 는 성준의 할 일 목록에 붙는 MCP 서버다. Cloudflare Worker 가
노션 DB 둘을 대신 읽고 쓴다. 성준은 이걸 브라우저 화면·바탕화면 위젯·claude.ai
에서도 같이 본다. **네가 넣은 것은 그 세 군데에 그대로 나타난다.**

DB 는 둘이다.

| | 누가 보나 |
|---|---|
| **팀** | 성준, 가영, 창준, 여림이 서로 다 본다. 주간 보고에도 올라간다 |
| **개인** | 성준만 본다. 보고에도 팀원에게도 절대 안 나간다 |

도구 : `list_todos` `list_done` `add_todo` `complete_todo` `uncomplete_todo`
`set_title` `set_memo` `set_due` `set_waiting` `set_today` `set_priority` `remove_todo`

## 넣을 때는 `source` 를 반드시 준다

성준 계정은 팀·개인 **둘 다** 쓸 수 있다. `add_todo` 에 `source` 를 안 주면
**서버가 거절한다.** 넣지 않고 되돌려보낸다 (2026-09-28 배포).

- 회사 업무 → `source: "팀"`
- 병원, 가족, 학업, 개인 재정, 개인 심부름 → `source: "개인"`
- 애매하면 **넣기 전에 성준에게 묻는다**
- 한 번에 여러 건을 받으면 용도별로 나눠 각각 넣는다

답에 어디로 갔는지가 찍힌다. **그걸 그대로 성준에게 전한다.**

```
넣었다: 팀 · 쇼피 발송 이슈 주기 점검 루틴 만들기
```

> **왜 이렇게 됐나** — 예전에는 `source` 를 안 주면 조용히 **개인**으로 갔다.
> 2026-09-28 에 업무 할 일 10건이 통째로 개인 DB 로 새어 들어가 팀원들이 못 봤다.
> 기본값을 팀으로 바꾸지는 않았다. 그러면 반대로 사적인 일이 팀 전원에게 보인다.
> 그래서 **고르게** 만들었다.

## 메모는 세 줄을 넘기지 않는다

메모는 **성준이 목록에서 훑어보는 줄**이다. 조사 보고서가 아니다.

- 첫 줄 : `결과물: <무엇이 나오면 끝인가>`
- 나머지 두 줄 : **없으면 일을 못 하는 것**만 — 기한 조건, 막고 있는 것,
  링크나 번호 하나
- **배경·경위·추정·통계는 적지 않는다.** 그건 슬랙과 원래 문서에 이미 있다
- 번호(주문번호, SKU, 송장, 바코드)는 **그 일을 집어드는 데 꼭 필요한 하나만**

네가 슬랙 스레드를 다 읽었다고 그걸 메모에 옮기지 않는다. 읽은 것이 아까워서
넣으면 열 줄짜리 메모가 되고, 목록이 안 읽힌다 — 실제로 그렇게 됐다.

```
좋음   결과물: 100개입 박스 규격 회신 받아 이재영 팀장님께 공유
       10/2 유선 문의함. 차주 복귀 후 답변 예정

나쁨   결과물: 코스메카 회신(100개입 박스 규격 가로세로높이, 분리 패킹 가능
       여부와 추가 작업비)을 이재영 팀장님께 슬랙 공유 - 10/2 코스메카 김진우님께
       유선 문의 후 글로 기록 보냄. 김진우님 차주 복귀 후 답변 요청 - 회신 요청 1:
       ... (여덟 줄 더)
```

## 모르는 것을 추측하지 않는다

이게 제일 중요하다. 2026-09-28 에 실제로 사고가 났다 — 한 세션이 성준에게
**이미 끝난 일을 안 끝났다고** 말했다. 코드 주석의 예시와 낡은 할 일 한 줄을
보고 추측한 것이다.

**하면 안 되는 추측 셋:**

1. **Cloudflare 시크릿 값을 코드에서 읽었다고 여기지 않는다.**
   `PERSONAL_CALENDAR_ID`, `CALENDAR`, `NOTION_TOKEN`, `SYNC_TOKEN`, `TEAM` 은
   전부 시크릿이라 **저장소 어디에도 값이 없다.** 코드 주석에 보이는
   `....@group.calendar.google.com` 같은 것은 **형식 예시**지 지금 들어 있는
   값이 아니다. 값이 궁금하면 **성준에게 묻는다.**

2. **DB 에 남아 있는 할 일을 시스템 상태의 근거로 쓰지 않는다.**
   할 일은 사람이 완료 처리해야 사라진다. **일은 끝났는데 줄이 안 지워진
   경우가 흔하다.** "이런 할 일이 남아 있으니 아직 안 된 것"은 틀린 추론이다.

3. **다른 세션이 한 일을 모른다.** 성준은 여러 저장소에서 동시에 일한다.
   네가 안 한 일이라고 안 일어난 것이 아니다.

셋 중 하나라도 걸리면 **단정하지 말고 이렇게 답한다** — "저장소에서는
확인이 안 됩니다. 시크릿/대시보드 쪽이라 성준님이 보셔야 합니다."

## 지금 참인 것 (2026-09-29 기준)

아래는 실제로 배포·확인된 것들이다. 이보다 최신 소식이 있으면 성준 말이 맞다.

- **개인 DB 항목이 가는 구글 캘린더는 `ghaos009@gmail.com` 으로 옮겨졌다.**
  2026-09-28 에 시크릿 `PERSONAL_CALENDAR_ID` 를 바꿔 배포했고, 성준이 개인
  일정 하나를 넣어 개인 캘린더에 뜨는 것과 완료 시 사라지는 것까지 눈으로 봤다.
  회사 일정은 그대로 회사 캘린더로 간다. **코드는 안 고쳤다** — 시크릿만 바꿨다.
- **`add_todo` 는 `source` 없이는 거절한다.** 위에 적은 그대로다.
- **Cloudflare Cron 트리거는 등록은 되는데 안 깬다.** 캘린더 맞추기는 화면을
  열 때 따라 도는 `maybeSync` 와, 밖에서 10분마다 두드리는 `/sync/<토큰>` 이
  대신한다. "왜 캘린더가 안 맞지"를 cron 탓으로 돌리지 않는다.

## 조심할 것

- **개인 DB 항목을 요약·보고·공유 문서에 섞지 않는다.** 성준이 화면에서 같이
  보는 것과, 남에게 나갈 글에 넣는 것은 다른 일이다
- **남의 할 일은 읽기만 된다.** `owner` 로 동료 것을 볼 수는 있지만 고치거나
  완료 처리하면 거부당한다. 그게 정상이다 — 그 사람에게 말해서 직접 하게 한다
- **잘못 넣었을 때 옮기는 도구는 없다.** 지우고 다시 넣으면 id 와 생성일이
  바뀐다. 그러지 말고 **성준에게 말한다** — 성준 쪽에서 진짜 이동이 된다
- `list_done` 은 **최근 7일 고정**이다. 인자로 못 바꾼다
