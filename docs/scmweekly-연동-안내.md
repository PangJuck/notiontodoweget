# 주간보고 스킬 : 이름 바꾸기 + Ulick To-do 붙이기

이 파일은 **주간보고(`weekly`) 스킬을 만든 Claude Code에게 주는 것**이다.
팀원은 안 읽어도 된다.

읽는 Claude에게 : 할 일이 둘이다.

1. **스킬 이름을 `weekly` → `scmweekly` 로 바꾼다** (아래 A)
2. **Ulick To-do 를 재료로 읽게 붙인다** (아래 B)

고치는 곳은 **「1. 수집 모드」 앞에 절 하나 끼우기** 와 **표 채우는 규칙 몇 줄**뿐이다.
나머지 절차는 건드리지 않는다.

문서 버전 : 2026-09-28.2 / 필요한 워커 : `ulick-todo` **1.5.0 이상**

---

# A. 이름을 `scmweekly` 로 바꾼다

팀의 다른 도구가 `/scmtodo` 라서 결을 맞춘다. 그리고 `weekly` 라는 이름이
다른 데도 있어서(아래 「짚어둘 것」) 겹치는 걸 없앤다.

## 바꿀 곳

```
~/.claude/skills/weekly/   ->  ~/.claude/skills/scmweekly/
```

폴더를 **옮긴다.** ⛔ 복사하고 옛것을 남기지 않는다. 남기면 `/` 목록에 둘 다 떠서
어느 쪽이 걸릴지 알 수 없다. `내정보.md` 는 같은 폴더 안에 있으니 같이 따라간다.

그다음 `scmweekly/SKILL.md` 의 frontmatter 를 고친다.

```yaml
---
name: scmweekly
description: SCM팀 주간보고. 이번 주 한 일을 말로 던지면 주간보고 양식으로 정리해 공용 노션 DB 「SCM 주간보고 (팀원)」에 등록한다. 사용자가 "scmweekly", 주간보고, 위클리, 이번주 정리를 요청하거나 /scmweekly 를 치면 반드시 사용한다.
---
```

## 같이 고쳐야 하는 것 넷

이름이 본문 여기저기 박혀 있다. 전부 찾아 바꾼다.

1. **SKILL.md 본문** 의 `weekly` 언급
2. **바탕화면 `주간보고/CLAUDE.md`** — 「`weekly` 스킬의 절차를 그대로 따른다」 줄
3. **설치 지시문 md** (팀원에게 나눠준 파일) — 경로 `~/.claude/skills/weekly/` 와
   마지막 안내의 `/weekly`. **이게 제일 중요하다.** 안 고치면 다음에 까는 사람이
   도로 옛 이름으로 깐다
4. **노션의 「SKILL.md 원본 (클로드 전용)」 페이지**(`3dcbd60b576281e58314e3a67228339e`) —
   자동 갱신이 여기서 받아간다. 여기가 옛 이름이면 **갱신될 때마다 이름이 되돌아간다**

## 이미 깐 사람 처리

설치 지시문의 1단계는 「`내정보.md` 가 있으면 재설치로 보고 묻지 않는다」 이다.
이름을 바꾸면 **새 경로에는 `내정보.md` 가 없어서** 이름을 다시 묻게 된다.

설치 지시문에 이 줄을 넣는다.

```markdown
**0. 옛 이름 정리 (이름을 바꾸기 전에 깐 사람만)**

`~/.claude/skills/weekly/` 가 있으면 :
1. 그 안의 `내정보.md` 를 `~/.claude/skills/scmweekly/내정보.md` 로 옮긴다
   (이러면 이름을 다시 묻지 않는다)
2. `~/.claude/skills/weekly/` 폴더를 지운다
3. 「옛 이름(weekly)에서 옮겼습니다」 한 줄만 알린다
```

## 바꾼 뒤 확인

- `/` 치고 `scm` → `scmtodo` 와 `scmweekly` 둘이 뜨나
- `weekly` 는 **안 떠야** 한다 (뜨면 옛 폴더가 남은 것)
- `/scmweekly` 로 평소처럼 도나

# B. Ulick To-do 를 붙인다

## 왜 붙이나

`scmweekly` 는 지금 **사람이 말로 던지는 것만** 받는다. 그런데 팀원들이 이미 한 주
내내 할 일을 **Ulick To-do** 에 적고 완료 처리하고 있다. 끝낸 일, 남의 회신을
기다리는 일, 다음 주 마감이 전부 거기 쌓여 있다.

그걸 안 읽으면 팀원이 **같은 것을 두 번 적는다.** 그리고 사람 기억으로 다시 적으면
빠진다 — 주간보고에서 제일 자주 나는 사고가 그것이다.

목표는 하나다. **팀원이 「이번 주 나 뭐했지」 하면 초안이 이미 절반 차 있는 것.**

⛔ To-do 를 읽는다고 수집 모드를 없애지 않는다. To-do 에 없는 일이 항상 있다
(회의, 갑자기 들어온 것, 남을 도운 것). To-do 는 **마중물이지 전부가 아니다.**

## Ulick To-do 가 무엇인가

노션 DB 하나(`Ulick 팀 할 일`)를 팀 넷(성준·가영·창준·여림)이 같이 쓴다.
한 행이 할 일 하나고, 아래 값을 갖는다.

| 값 | 뜻 |
|---|---|
| `할 일` | 제목. 동사형으로 적기로 돼 있다 |
| `담당자` | 성준 / 가영 / 창준 / 여림 |
| `완료`, `완료일` | 끝냈는가, 언제 |
| `마감일` | 언제까지 |
| `우선순위` | 4사분면. 1 지금 당장 / 2 핵심 업무 / 3 빠르게 쳐낼 / 4 언젠가 |
| `대기중` | **남의 회신을 기다리는 중** |
| `메모` | 결과물 정의와 잘린 맥락. `결과물: 비교표 1장` 같은 것 |

팀원은 노션을 직접 안 본다. 브라우저 화면이나 자기 Claude Code 로만 쓴다.

## 어떻게 읽나

팀원의 Claude Code 에는 **`ulick-todo` MCP 서버**가 이미 붙어 있다
(주간보고와 별개로, 개인 DM 으로 받은 설정 파일로 깔았다).
`claude mcp list` 에 `ulick-todo` 가 보이면 된 것이다.

**신원은 그 사람의 서비스 토큰으로 정해진다.** `owner` 를 안 주면 자기 것만 온다.
⛔ 이름을 직접 넘겨 남인 척할 수 없다. 그럴 필요도 없다.

### `list_done` — 최근 7일 끝낸 일

```
- 2026-09-16  3PL 견적서 3곳 비교표 1장 만들기  (가영)
    메모: 결과물: 비교표 1장 / 오배송률 위주
- 2026-09-15  이펙터 드랍테스트 보고서 만들기  (가영)
```

`완료일 / 제목 / 담당자` 와, 있으면 `메모` 가 온다.
**딱 7일이다.** 주간보고 주기와 같아서 인자 없이 부르면 된다.

### `list_todos` — 남은 일

```
오늘 2026-09-28. 남은 할 일 12건.

[1 지금 당장 (중요+시급)]
- 자재 입고일 업체에 확인하기  (대기중, 마감 2026-09-29, 가영)
    메모: 부스터 프로 20ml 조립 발주 건
    id: 3e81c05f-ccf7-8168-9e18-ec3520b953f9
```

사분면별로 묶여 오고, 괄호 안에 `오늘의3` `대기중` `마감 날짜` `담당자` 가 붙는다.

### `add_todo` — 할 일 넣기

`title`, `due`(YYYY-MM-DD), `quadrant`(1~4), `memo`, `source`(`팀`) 을 받는다.

## SKILL.md 를 이렇게 고친다

### 고치는 곳 하나 : 「1. 수집 모드」 **앞에** 이 절을 끼운다

```markdown
## 0.5 To-do 에서 먼저 긁어온다

`ulick-todo` 도구가 보이면 수집 모드로 들어가기 **전에** 아래를 한다.
안 보이면 이 절을 통째로 건너뛰고 바로 1번으로 간다. ⛔ 깔라고 조르지 않는다.

1. `list_done` 을 인자 없이 부른다 (내 것, 최근 7일)
2. `list_todos` 를 인자 없이 부른다 (내 남은 일)
3. 받은 것을 **표 초안으로 미리 채워** 사용자에게 보여준다. 이때 한 줄만 붙인다 :

   > To-do 에서 N건 끌어왔습니다. 여기 없는 것만 마저 던져주세요.

4. 그다음 평소대로 수집 모드로 들어간다.

⛔ To-do 에서 온 것을 **확정으로 취급하지 않는다.** 사용자가 「이건 빼」 하면 뺀다.
⛔ To-do 가 비어 있어도 사과하거나 설명하지 않는다. 그냥 1번으로 간다.
```

### 어느 표로 가나

| To-do 에서 | 가는 곳 | 왜 |
|---|---|---|
| `list_done` 의 모든 행 | **3. 한 일** | 완료된 것만 담는 표라 정확히 맞는다 |
| 그중 결과가 굵은 것 | **1. 이번 주 결과** | 원래 3번에서 끌어올리게 돼 있다 |
| `list_todos` 중 **`대기중`** | **5. 막힌 것** | 대기중은 「남의 회신을 기다림」이다. 5번 그 자체다 |
| `list_todos` 중 마감이 다음 주 | **4. 다음 주** | |
| `list_todos` 중 **마감이 지난 것** | **5. 막힌 것** | 지났는데 안 끝났으면 뭔가 막힌 것이다. 왜 막혔는지 묻는다 |

`3 빠르게 쳐낼` 과 `4 언젠가` 는 **보고에 올리지 않는다.** 잡무다.

### 칸을 채울 때

- `건` ← `할 일` 제목 그대로. ⛔ 다듬는다고 줄이지 않는다
- `결과` ← **`메모`가 주 재료다.** 메모가 없으면 **반드시 묻는다.**
  ⛔ 제목만 보고 결과를 지어내지 않는다. 「무엇이 바뀌었나」는 To-do 에 없는 정보다
- `연관자` ← To-do 에는 없다. **항상 사용자에게 묻는다**
- `제품` ← 제목이나 메모에 있으면 쓰고, 없으면 묻는다
- `기한` ← `마감일` 그대로 (m/d 로 바꿔서)
- `누가 무엇을 해줘야 풀리나` ← To-do 에는 없다. **`대기중` 행마다 반드시 묻는다**

⛔ **To-do 에서 왔다고 「반드시 묻는 칸 셋」을 면제하지 않는다.**
`결과`, `물음`, `누가 무엇을 해줘야 풀리나` 는 그대로 전부 묻는다.
To-do 는 **행을 만들어 줄 뿐, 칸을 채워 주지 않는다.**

### 다 끝나고 : 다음 주를 To-do 로 되돌린다

등록(6번)이 끝나면 한 번만 묻는다.

```markdown
「4. 다음 주」에 적은 N건, Ulick To-do 에도 넣어둘까요?
```

하겠다고 하면 `add_todo` 로 넣는다. `due` 는 표의 기한, `quadrant` 는 2,
`memo` 에는 「끝나면 무엇이 되나」 칸을 넣는다.

⛔ 묻지 않고 넣지 않는다. ⛔ 거절하면 그걸로 끝이다.

**이게 고리를 닫는 자리다.** 다음 주에 `list_done` 이 그것들을 도로 꺼내 온다.
그리고 「2. 지난 회차 대조」가 훨씬 정확해진다 — 지난주 4번에 적은 것이 실제로
끝났는지를 기억이 아니라 기록으로 확인하게 된다.

# 짚어둘 것

## `weekly` 라는 이름이 아직 한 군데 더 있다

| | 누가 → 누구에게 | 무엇 |
|---|---|---|
| **이 스킬** (`scmweekly`) | 팀원 → 팀장 | 표 다섯. 공용 노션 DB 에 등록 |
| `ulick-todo` MCP 의 `weekly` **프롬프트** | 팀장 → 본부장 | 네 덩어리 요약. 등록 안 함 |

이름을 `scmweekly` 로 바꿔서 `/` 목록에서는 안 겹치지만, **MCP 프롬프트 쪽은
그대로 `weekly` 다.** 성준(팀장)만 쓴다. 팀원 Claude 에도 보일 수는 있으니,
절차를 섞지 않는다. 헷갈리면 **이 스킬(`scmweekly`)이 팀원용**이다.

## 「대기중」과 「막힌 것」은 같은 말이 아니다

`대기중` 은 **켜져 있다는 사실**만 말한다. 5번 표가 요구하는
`무엇이 막혔나` 와 `누가 무엇을 해줘야 풀리나` 는 그 안에 없다.
`대기중` 행은 **전부 되묻기 대상**이다. 이건 질문 3개 상한 밖이다.

# 붙이고 나서 확인할 것

1. `/` 치고 `scm` → `scmtodo` 와 `scmweekly` 둘이 뜨고 `weekly` 는 안 뜨나
2. 팀원 Claude Code 에서 `claude mcp list` → `ulick-todo` 가 보이나
3. `/scmweekly` 를 쳤을 때 **아무것도 안 던졌는데** To-do 에서 긁어온 초안이 먼저 뜨나
4. `ulick-todo` 가 없는 사람이 `/scmweekly` 를 쳐도 **예전 그대로** 도나
   (이게 제일 중요하다. 없는 사람이 막히면 안 된다)
