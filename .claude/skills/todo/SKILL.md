# To-do 기록

## 대상

DB가 둘이다. 구조는 같고 용도만 다르다.

| 용도 | data_source_id | 위치 |
|---|---|---|
| 업무 | `5ead04e6-65a7-4e98-9b3c-a8dfffdf5001` | 회사 팀 페이지 |
| 개인 | `bd927ce1-075b-4b3a-b98a-7c823cbb6cfd` | 개인 워크스페이스 |

**어디에 넣을지 먼저 정한다.** 업무 DB가 있는 페이지는 링크가 있는 사람 누구나 볼 수 있다. 결혼 준비, 학업, 병원, 가족, 개인 재정 같은 항목은 반드시 개인 DB로 간다. 회사 업무는 업무 DB로 간다. 어느 쪽인지 애매하면 넣기 전에 묻는다.

한 번에 여러 항목을 받으면 용도별로 나눠 두 번 호출한다.

속성명은 정확히 이대로다.

| 속성 | 타입 | 비고 |
|---|---|---|
| `할 일` | 제목 | 가운데 공백 있음 |
| `우선순위` | 선택 | 4사분면. 아래 표 참고. 앞 숫자 1~4가 기준 |
| `완료` | 체크박스 | 기록할 때 `"__YES__"`, `"__NO__"` |
| `오늘의 3` | 체크박스 | 오늘 반드시 끝낼 것. 최대 3개 |
| `대기중` | 체크박스 | 남의 회신을 기다리는 중이면 켠다 |
| `마감일` | 날짜 | 캘린더 뷰의 축 |
| `분류` | 선택 | 옵션은 성준이 노션에서 직접 늘린다 |
| `완료일` | 날짜 | 완료 버튼이 채운다. 스킬이 완료 처리할 때도 함께 채운다 |
| `메모` | 텍스트 | 결과물 정의, 잘린 맥락 |

노션 MCP로 접근한다. 바탕화면 위젯이 쓰는 Integration 토큰과는 별개다.

## 4사분면

`우선순위` 값은 이 넷 중 하나다. 글자 그대로 써야 위젯과 노션 보드가 같은 칸으로 읽는다.

| 값 | 뜻 | 다루는 법 |
|---|---|---|
| `1 지금 당장 (중요+시급)` | 오늘 안 하면 터지는 일 | 오전에 먼저 친다 |
| `2 핵심 업무 (중요+안시급)` | 아무도 안 재촉하는데 안 하면 나중에 1번이 되는 일 | 매일 한 칸씩. 여기가 비면 하루가 잡무로 끝난다 |
| `3 빠르게 쳐낼 (안중요+시급)` | 누가 기다리지만 오래 붙들 가치는 없는 잡무 | 모아서 오후에 한 번에 |
| `4 언젠가 (안중요+안시급)` | 지금은 아닌데 버리기도 아까운 것 | 한 달에 한 번 꺼내 올리거나 지운다 |

**옵션 이름은 노션에서 바뀔 수 있다.** 값을 쓸 때는 노션에 실제로 들어 있는 옵션 이름을 그대로 써야 한다. 확실하지 않으면 먼저 DB 스키마를 조회해 현재 옵션 이름을 확인한다. 판단은 앞 숫자 1~4로 한다.

**기록할 때 항상 사분면을 정한다.** 비워두지 않는다. 판단이 애매하면 추정값을 넣고 "이렇게 넣었는데 맞냐"고 결과에 함께 알린다. 성준이 아니라고 하면 바꾼다.

판단 기준:
- **시급한가** = 마감이 오늘내일인가, 남이 나를 기다리고 있나
- **중요한가** = 안 하면 뒤탈이 큰가, 내 평가나 커리어에 남는가

## 기록 규칙

1. 한 항목 = 한 페이지. 한 문장에 두 가지 일이 섞여 있으면 쪼갠다
2. **동사형으로 쓴다.** `마케팅 기획서` 아니고 `오후 3시까지 마케팅 기획서 초안 1페이지 작성`. 행동과 기한을 세트로 붙인다
3. **덩어리는 원자 단위로 쪼갠다.** `신제품 런칭`처럼 큰 덩어리가 오면 `경쟁사 사이트 3개 캡처`, `타겟 연령층 5명 설문`처럼 바로 손이 움직이는 크기로 나눈다. 쪼갠 결과를 먼저 보여주고 넣을지 묻는다
4. `완료`는 항상 `"__NO__"`로 넣는다
5. **마감부터 확인한다.** 시점을 안 말했으면 "언제까지냐"고 한 번 묻는다. 그래도 없으면 비운다. 추측해서 채우지 않는다
6. **내 마감은 공식 마감보다 하루 먼저 잡는다.** 성준이 "금요일까지"라고 하면 `마감일`은 목요일로 넣고 `메모`에 `공식 마감 9/19`를 남긴다. 그리고 결과에 "하루 당겨 넣었다"고 알린다. 마감이 내일 이내면 당기지 않는다
7. 상대 표현은 오늘 날짜 기준 절대 날짜로 바꾼다. 내일, 다음 주 화요일, 이번 달 말, 금요일까지 등
8. "곧", "조만간", "언제 한번"은 날짜를 비우고 `4 언젠가` 후보로 본다
9. **결과물이 뭔지 적는다.** 산출물이 있는 일이면 `메모`에 `결과물: 대표님 보고용 PPT 5장` 형태로 남긴다. 끝이 정의되면 일이 길어지지 않는다
10. `대기중`은 남의 회신, 타 부서 자료, 승인을 기다리는 일이면 켠다. 내 손을 떠난 일과 내가 지금 할 일이 섞이면 머리가 복잡해진다
11. `분류`는 **DB에 이미 있는 옵션 중에서만** 고른다. 새 값이 필요해 보이면 임의로 만들지 말고 묻는다. 애매하면 비운다
12. **새 일이 들어오면 우선순위를 다시 본다.** 새 항목이 `1 지금 당장`이면, 기존 `1 지금 당장`과 `오늘의 3` 중 무엇을 미룰지 함께 제안한다

## 쓰기

`notion-create-pages`로 한 번에 전부 만든다. 항목마다 호출하지 않는다.

```
parent: {"data_source_id": "5ead04e6-65a7-4e98-9b3c-a8dfffdf5001"}   # 개인 항목이면 bd927ce1-075b-4b3a-b98a-7c823cbb6cfd
properties: {
  "할 일": "오후 3시까지 3PL 견적서 3곳 비교표 1장 작성",
  "완료": "__NO__",
  "우선순위": "1 지금 당장 (중요+시급)",
  "오늘의 3": "__NO__",
  "대기중": "__NO__",
  "분류": "업무",
  "date:마감일:start": "2026-09-12",
  "date:마감일:is_datetime": 0,
  "메모": "결과물: 비교표 1장. 가격보다 오배송률 위주로"
}
```

날짜가 없으면 `date:마감일:*` 키를 아예 뺀다. 시각까지 지정된 경우에만 `is_datetime`을 1로 두고 `start`에 ISO datetime을 쓴다.

## 조회

두 DB 모두에서 `완료`가 `"__NO__"`인 것만 가져와 합친다. 기본은 **사분면 순서**로 보여준다. 항목마다 업무인지 개인인지 표시한다.

1. `오늘의 3` — 켜진 것이 있으면 항상 맨 위에 따로
2. `1 지금 당장`
3. `2 핵심 업무`
4. `3 빠르게 쳐낼`
5. `4 언젠가`
6. 사분면이 비어 있는 항목 — 있으면 "미분류 N건, 지금 나눌까" 하고 묻는다

`대기중`인 항목은 끝에 `(대기)`를 붙인다.

"날짜순으로", "이번 주 뭐 있어" 하면 마감일 기준으로 바꿔 묶는다. 지난 것(마감일 < 오늘)은 있으면 항상 맨 위. 그다음 오늘, 이번 주(일요일까지), 이번 달, 날짜 미정.

"회사 것만", "개인 것만" 하면 해당 DB만 본다.

## 아침 루틴

"아침 정리", "오늘 뭐부터", "출근했어" 같은 요청이면 이걸 돌린다. 10분 안에 끝내는 게 목적이다.

1. 어제 켜둔 `오늘의 3`을 전부 끈다. 어제 못 끝낸 것이 있으면 먼저 알린다
2. 미완료 전부 가져와 사분면이 빈 항목을 추려 배치안을 제안한다. 성준이 확인하면 한 번에 반영한다
3. 마감이 지난 항목을 짚는다. 다시 잡을지, 버릴지 묻는다
4. **오늘 끝낼 3개를 고르게 한다.** `1 지금 당장`에서 먼저, 그다음 `2 핵심 업무`에서 최소 하나. 3개를 넘기지 않는다. 정해지면 `오늘의 3`을 켠다
5. 배치를 한 줄로 제안한다. 오전에는 `1 지금 당장`과 `2 핵심 업무`처럼 머리 쓰는 일, 오후에는 `3 빠르게 쳐낼`을 몰아서
6. `대기중` 항목 중 사흘 넘게 묶여 있는 것이 있으면 "이건 오늘 한 번 찔러보라"고 짚는다

`2 핵심 업무`가 `오늘의 3`에 하나도 없으면 그냥 넘어가지 말고 한 번 짚는다. 그날은 잡무로만 끝난다.

## 퇴근 루틴

"퇴근 정리", "오늘 마무리", "퇴근할게" 같은 요청이면 이걸 돌린다.

1. 오늘 `완료`된 항목을 가져와 **3줄로 요약**한다. 무슨 일이 몰렸는지 한 줄 덧붙인다
2. 못 끝낸 `오늘의 3`이 있으면 내일로 넘길지 묻고, `오늘의 3`을 끈다
3. **내일의 첫 행동 3가지**를 정해 `오늘의 3`을 미리 켜둔다. 내일 아침 멍 때리는 시간을 없애는 게 목적이다
4. `4 언젠가` 칸에 쌓인 것을 보여주고 지울지 묻는다
5. 새 일을 벌이지 않는다. 퇴근 직전에 들어온 일은 내일 `1 지금 당장`으로 넣고 끝낸다

## 완료 처리

`notion-update-page`로 `완료`를 `"__YES__"`로 바꾸고, `date:완료일:start`에 오늘 날짜, `오늘의 3`을 `"__NO__"`로 함께 넣는다. 셋 중 하나만 바꾸면 기록 뷰가 비거나 날짜가 빈다. 페이지를 지우지 않는다.

노션에서 직접 처리할 때는 체크박스 대신 `완료버튼`을 누른다. 버튼이 값을 같이 채운다.

어떤 항목인지 애매하면 후보를 보여주고 고르게 한다. 짐작으로 처리하지 않는다.

## 지난 기록 되짚기

"지난주에 뭐 했지", "9월 정리해줘" 같은 요청이면 `완료`가 `"__YES__"`인 항목을 `완료일` 범위로 걸러 온다.

**사분면별로 묶어 보여준다.** `2 핵심 업무` 비중이 낮으면 그 주는 잡무로 갔다는 뜻이니 한 줄로 짚는다. 숫자만 나열하지 않는다.

`완료일`이 빈 완료 항목이 보이면 체크박스를 직접 눌러 처리한 것이다. 언제 끝냈는지 물어서 채워준다.

## 확인이 필요한 경우

- 한 덩어리를 여러 항목으로 쪼갰을 때는 결과를 먼저 보여주고 그대로 넣을지 묻는다
- 같은 내용이 이미 미완료로 있으면 중복으로 넣지 말고 알린다
- `오늘의 3`이 이미 3개인데 하나 더 넣으려 할 때는 무엇을 뺄지 묻는다
- 새 `분류` 값이 필요해 보일 때
- 회의 관련 항목이면 "이 회의에 내가 왜 필요한지" 한 번 묻는다. 답이 안 나오면 `4 언젠가`이거나 거절할 일이다

## 응답 형식

- 기록한 항목을 한 줄씩. 제목, 사분면, 마감일, 분류만
- 이모지는 쓰지 않는다
- 가운뎃점 대신 쉼표를 쓴다
- 마감을 하루 당겼거나 사분면을 추정했으면 그 사실을 마지막에 한 줄로 알린다
